# ui-compare（修正前後の画面比較）

最後のコミット（既定 HEAD）の画面＝修正前、今の作業ツリーの画面＝修正後として、見比べる自己完結 HTML を `/private/tmp/claude-<uid>/<プロジェクトの識別名>/ui-compare/<日時>_<slug>/index.html`（プロジェクトの外の一時領域。識別名は git ルートの絶対パスの英数字以外を `-` にしたもの）に作る。プロジェクト内にはファイルを作らない。v1 の対象は Node 系の開発サーバー（`package.json` の dev 等）。作業ツリー・index・ref には書き込まない（修正前のソースは `git archive` で一時ディレクトリへ展開して使う）。

## 手順

1. **基準 `--base`**：引数に `--base <rev>` があればそれ。無ければ HEAD。ただし HEAD と作業ツリーに差分（`git diff HEAD --name-only` と未追跡ファイル）が無いときは推測せず、AskUserQuestion で基準のコミットを聞く（候補：デフォルトブランチとの merge-base、直前の数コミットなど）。
2. **撮るパス**：`git diff --name-only <base>` と `git ls-files --others --exclude-standard` から変わったファイルを見て、フレームワークのルーティング（Next の `app/`・`pages/`、React Router の定義等）から対応する URL パスを決める。
   - **直接修正したページ**（ルートに対応するページファイル・ページコンポーネント・テンプレート等）は**上限なしで全部撮る**。
   - 共通部品（レイアウト・ヘッダー等の共有コンポーネント・共通 CSS など）の修正で影響を受けるページは、直接修正したページと合わせて **30 ページ以下なら聞かずに全部撮る**。**30 ページを超えるときは推測で絞らず** AskUserQuestion で聞く（直接修正したページは常に含める。選択肢の例：「直接修正したページ＋代表的な数ページ（推奨。ページ名を挙げる）」「影響する全ページ（N ページ・撮影に約 N×幅数×2 秒）」。Other で個別指定も可）。
   - 決められなければ `/` だけにし、報告でそう伝える。
   - 判断材料：ページが多くても Claude は画像を読まないのでトークンはほぼ増えない。撮影は修正前・修正後の 2 枚で 1 ページ×1 幅あたり約 2 秒（Next 等の dev は各ページの初回表示でコンパイルが走り、さらに延びる）。
3. **起動コマンド `--cmd`**：`package.json` の scripts とフレームワークから `{port}` を含むコマンドを決める（npm の場合：Vite は `npm run dev -- --port {port} --strictPort`、Next は `npm run dev -- -p {port}`、その他は `PORT={port} npm run dev`）。パッケージマネージャは lockfile に合わせる。**`--` が要るのは npm だけ**：pnpm・yarn・bun は `--` を付けない（`pnpm run dev --port {port} --strictPort`、Next なら `pnpm run dev -p {port}`）。pnpm は `--` をそのままスクリプトに渡すため、付けると Vite が `--port` を無視し、Next は `-p` をディレクトリと解釈して失敗する。`flake.nix` があればスクリプトが自動で devShell（`nix develop`）経由で起動・インストールするので、`--cmd` に `nix develop -c` を付けない。アプリがリポジトリのサブディレクトリにあるときは `--dir <ルートからの相対パス>` を渡す。セッション中に修正後の開発サーバーを起動していて URL が分かっているときは `--after-url <URL>` を渡す（同じフォルダで dev サーバーを 2 本起動すると、フレームワークによっては失敗するか、動いている方を乱すため）。
4. **`--slug`**（英小文字・数字・ハイフン、30 文字以内）と **`--title`**（HTML 見出し用。日本語可。引数の説明、無ければ差分から短く要約）を決める。
5. `bash ${CLAUDE_SKILL_DIR}/ui-compare.sh --title ... --slug ... --cmd '...' --path / [--path ...] [--base ...] [--dir ...] [--after-url ...]` を **Bash の `timeout` は `600000`** にして実行する（依存のインストールや起動待ちで 120 秒を超えることがある）。撮るページ×幅が 30 を超えるときは 10 分の上限を超えうるので、`run_in_background` で実行して完了の通知を待つ。
   - **終了コード 3**：`--after-url` 無しで、アプリのディレクトリに開発サーバーらしきもの（ユーザーが起動したもの等）が既に動いていたため中止した。スクリプトが候補の URL とコマンドを出すので、推測で選ばず、AskUserQuestion でどれを修正後として使うかユーザーに聞き、答えに沿って再実行する（候補のどれかを使う → `--after-url <その URL>`、どれも修正後の開発サーバーではない（Storybook 等）→ `--start-after`）。候補のプロセスを止めたり触ったりしない。
6. **報告**：スクリプトが最後に出す URL（`file:///...`）をそのまま貼り、変化率の表を添える。出力は一時領域なので再起動などで消えることを 1 行添える（毎回くどくならない程度に）。**画像ファイルは Read しない**（トークン節約）。失敗したらスクリプトのエラーをそのまま伝え、作業ツリーを直そうとしない。

## 既知の制約

- 修正前のソースは `git archive` で展開するため、Git LFS の実体はポインタのまま、submodule の中身は含まれず、`export-ignore` 指定のファイルは除かれる。該当しそうなリポジトリではスクリプトが警告を 1 行出す（中止はしない）。修正前側で画像等が欠けて見えたらこれが原因の可能性があると報告に添える。
- 修正前の依存は、lockfile（モノレポでは最寄りの親の lockfile）が基準と同一なら作業ツリーの `node_modules` を APFS clonefile で複製して流用し、違えば修正前側でインストールする。
- 既存の開発サーバーの検出はヒューリスティックで、`/` がヘッダなしでリダイレクトするアプリや、初回コンパイル中で 2 秒以内に応答しないサーバーは見逃すことがある（そのときは修正後側を 2 本目として起動する）。ユーザーが開発サーバーを動かしているのが分かっているときは `--after-url` を渡す。
- git に含まれないビルド出力（モノレポの内部パッケージの `dist/` など、事前に build して参照する構成）は修正前側に無い。修正前側だけがエラー画面になったら、これが原因の可能性があると報告に添える（修正前側で build はしない）。
- devShell は作業ツリー側の flake を修正前・修正後の両方に使う（基準コミットで flake.nix の版が違っても、今の devShell で動かす）。
- 出力は一時領域（`/private/tmp/claude-<uid>/...`）なので、Mac の再起動や OS の定期的な掃除で消える。残したい比較結果はユーザーが別の場所へコピーする。
