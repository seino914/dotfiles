# git pull（デフォルトブランチを最新化）

`bash ${CLAUDE_SKILL_DIR}/pull.sh` をカレントディレクトリで実行し、出力をそのまま報告する。**Bash ツールの `timeout` は `600000` にして実行する**（配下のリポジトリが多いと既定の 120 秒を超えることがあり、途中で打ち切られると切り替え直後のリポジトリがデフォルトブランチのまま残る）。

- カレントディレクトリが git リポジトリならそのリポジトリだけ、そうでなければ配下（3 階層まで）のリポジトリすべてが対象。見つけたリポジトリの内側（入れ子）は見ない。ホームディレクトリとその上位（`/Users`・`/` 等）では実行を拒否する
- 各リポジトリで、デフォルトブランチ（origin/HEAD）を求め、fetch し、デフォルトブランチへ切り替えて `git merge --ff-only origin/<デフォルトブランチ>` で取り込む（`pull.rebase` 等の設定に左右されず、rebase はしない）
- 次のリポジトリはスキップする：detached HEAD のもの、デフォルトブランチが分からないもの、追跡ファイルに未コミットの変更があるもの。fetch・切り替え・取り込み（fast-forward できない等）に失敗したリポジトリは git のエラーを添えて失敗と出る。切り替えてから失敗した場合は元のブランチへ戻し、戻せたかどうかも出る
- 切り替えや取り込みで .gitignore 対象のファイル（例：手元の `.env`）が上書きされないかの事前確認はしない
- 出力は 1 リポジトリ 1 行。先頭記号は `✓` 更新・`=` 既に最新・`-` スキップ／失敗。ブランチを切り替えたときは `feature/x → main` のように元のブランチ名も出るので、報告でも省かずに伝える（元からデフォルトブランチなら `main` だけ）
- スキップ・失敗したリポジトリを自分で直そうとしない（stash・rebase・reset・追加の git 操作をしない）。理由を添えて報告するだけにする
