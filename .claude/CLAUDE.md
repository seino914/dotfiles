# Git操作の制限

`git commit`・`git push`・PR作成（`gh pr create`）は、ユーザーが `/pr` と明示的に指示した `/pr` スキルの実行中に限り許可される。それ以外では絶対に実行せず、作業が完了しても変更はワーキングツリーに残したまま内容を報告する。

# 変更後の検証

- プロジェクトに検証手段（lint・型チェック・テスト・ビルド等）があれば、変更後に必ず実行して通す。落ちたら自分で直す（自分の変更と無関係な既存の失敗は直さず報告する）
- `/pr` の前は必ず通す。通っていない状態でコミットしない

# パッケージインストールの制限（Nix運用）

グローバル環境は `~/Dev/seino914/dotfiles` のNix設定（nix-darwin + home-manager）で宣言管理している。開発中に環境を勝手に変更しない。

- `brew install`・`npm install -g`・`pip install --user` など、プロジェクト外に影響する恒久的なインストールは、ユーザーの明示的な指示があるときのみ行う
- ツールやランタイムが必要になったら、そのリポジトリの `flake.nix` devShell（`pkgs.mkShell`）に宣言して `nix develop` 経由で使う（既存のdevShellがあればそこに追記）
- 一時的な動作確認は `nix shell nixpkgs#<パッケージ>` / `nix run` でよい（環境に痕跡が残らない）
- lockファイルで管理されるプロジェクトローカルの依存（`npm install`・`pnpm add` 等）は通常どおり使ってよい
- グローバル（dotfilesの `nix/packages.nix` 等）に追加すべきと判断しても、勝手に追加せずユーザーに提案する
- 新しいプロジェクトの開発環境を用意するときは `nix-setup` スキル（Nix devShell + direnv）に従う

# モデル運用ポリシー（オーケストレーター / 実装の分離）

トークン節約のため、メインセッション（Fable 5.1）は**要件整理・設計・タスク分解・サブエージェントへの指示・成果物の監査レビュー・最終判断に専念**し、実装はサブエージェントに切り出す。

- 通常の実装（コード作成・修正、テスト作成、定型的なリファクタリング）は `model: "sonnet"`、難易度が中〜高のタスク（複雑なロジック、横断的な変更）は `model: "opus"` を Agent ツールで指定する
- 調査・探索も同様にサブエージェント（Explore 等）へ委譲してメインのコンテキストを温存する。`model: "sonnet"`（軽い調査なら `"haiku"`）を明示する（省略すると親の Fable 5.1 を継承してしまう）
- 例外：繊細な設計判断と実装が不可分な特に難しい箇所は、メインセッションが直接実装してよい
- サブエージェントへの指示は自己完結させる（対象ファイル、設計方針、制約、完了条件を明記）
- 独立したタスクは複数サブエージェントを並列起動する
- サブエージェントの成果物はメインセッションが必ずレビューしてから完了とする
