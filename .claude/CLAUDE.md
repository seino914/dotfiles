# Git操作の制限

- ユーザーが `/pr` と明示的に指示するまで、`git commit`・`git push`・PR作成（`gh pr create`）を絶対に実行しないでください。
- 作業が完了しても勝手にコミットせず、変更はワーキングツリーに残したまま内容を報告してください。
- コミット・push・PR作成は `/pr` スキルの実行中に限り許可されます。

# モデル運用ポリシー（オーケストレーター / 実装の分離）

トークン節約のため、メインセッション（Fable 5）は**設計・監査・レビューに専念**し、実装作業は適切なモデルのサブエージェントに切り出して実行すること。

## 役割分担

- **メインセッション（Fable 5）**: 要件整理、設計、タスク分解、サブエージェントへの指示、成果物の監査・レビュー、最終判断
- **サブエージェント（Sonnet）**: 通常の実装作業（コード作成・修正、テスト作成、定型的なリファクタリング）。Agent ツールで `model: "sonnet"` を指定
- **サブエージェント（Opus）**: 実装難易度が中〜高のタスク（複雑なロジック、横断的な変更）。`model: "opus"` を指定
- **例外**: 実装難易度が特に高い箇所（繊細な設計判断と実装が不可分な場合など）は、メインセッションが直接実装してよい

## 運用ルール

- サブエージェントへの指示は自己完結させる（対象ファイル、設計方針、制約、完了条件を明記）
- サブエージェントの成果物はメインセッションが必ずレビューしてから完了とする
- 独立したタスクは複数サブエージェントを並列起動する
- 調査・探索も同様にサブエージェント（Explore 等）へ委譲し、メインセッションのコンテキストを温存する。その際も `model: "sonnet"`（軽い調査なら `"haiku"`）を明示的に指定する（省略すると親の Fable 5 を継承してしまうため）
